1. INTRODUCTION                                           *neos-fusion-intro*

neos-fusion.nvim brings support for Neos CMS, Neos.Fusion and AFX to Neovim:

    - filetype detection for `.fusion`
    - syntax highlighting through Tree-sitter, with Vim syntax as a fallback
    - block indentation for Fusion and AFX
    - comment and indentation options
    - snippets for common Fusion prototypes
    - integration of the `neos-fusion-ls` language server

The plugin can be loaded without |neos-fusion-setup|; the defaults then apply.

==============================================================================
2. REQUIREMENTS                                    *neos-fusion-requirements*

    Neovim         0.10 or newer (tested with 0.12)
    Node.js        for the language server
    npm            only for :NeosFusionInstallServer

Optional:

    nvim-treesitter        parser `fusion` (:TSInstall fusion)
    LuaSnip                snippets, automatic
    blink.cmp              snippets, through a search_paths entry
    blink.cmp / nvim-cmp   completion capabilities (detected automatically)

nvim-lspconfig is NOT required.

==============================================================================
3. INSTALLATION                                    *neos-fusion-installation*

With lazy.nvim, local directory: >lua

    {
      dir = "~/src/neos-fusion.nvim",
      name = "neos-fusion.nvim",
      ft = { "fusion" },
      dependencies = {
        { "nvim-treesitter/nvim-treesitter", optional = true },
        { "L3MON4D3/LuaSnip", optional = true },
      },
      opts = {},
    }
<
From a GitHub repository: >lua

    { "<owner>/neos-fusion.nvim", ft = { "fusion" }, opts = {} }
<
Both dependencies are optional. If you need the commands without an open
Fusion file, add `cmd = { "NeosFusionInstallServer" }`.

Then, once: >vim

    :NeosFusionInstallServer
<
Nothing is ever downloaded automatically.

5. OPTIONS                                              *neos-fusion-options*

filetypes.fusion                              *neos-fusion-opt-filetypes*
        boolean, default `true`
        Detect `.fusion` as filetype `fusion`.

filetypes.afx
        boolean, default `false`
        Detect `.afx` as `fusion` too. Uncommon in Neos: AFX is a DSL inside
        Fusion, not a file extension of its own.

syntax                                            *neos-fusion-opt-syntax*
        boolean, default `true`
        Load the bundled Vim syntax. Tree-sitter still takes precedence as
        soon as it runs for the buffer. With `false` only Tree-sitter applies.

treesitter.enable                             *neos-fusion-opt-treesitter*
        boolean, default `true`
        Calls |vim.treesitter.start()| if the parser `fusion` is available.

treesitter.notify_missing
        boolean, default `false`
        Warn once when the parser is missing.

editor.commentstring                              *neos-fusion-opt-editor*
        string, default `"// %s"`
        Alternative: `"# %s"`.

editor.indent, editor.shiftwidth, editor.expandtab
        boolean / number / boolean, defaults `true`, `4`, `true`

snippets.luasnip                                *neos-fusion-opt-snippets*
        "auto" | boolean, default `"auto"`
        Registration with LuaSnip or blink.cmp. With `true` a warning is
        emitted when no engine is found. The key name is historical.

server.enable                                     *neos-fusion-opt-server*
        boolean, default `true`

server.autostart
        boolean, default `true`
        Start automatically on filetype `fusion`.

server.cmd
        string[] | nil, default `nil`
        Explicit start command. Takes precedence over all auto-detection: >lua
            cmd = { "node", "/path/out/main.js", "--stdio" }
<
server.node, server.npm
        string, defaults `"node"`, `"npm"`

server.version
        string, default `"0.3.16"`
        Installed by :NeosFusionInstallServer as `neos-fusion-ls@<version>`.

server.install_dir
        string | nil, default `nil`
        Without a value: `stdpath("data")/neos-fusion.nvim/server`.

server.prefer_local
        boolean, default `true`
        Prefer `<root>/node_modules/neos-fusion-ls/out/main.js`.

server.sanitize_stdout
        boolean, default `true`
        Start the server through `bin/neos-fusion-ls-stdio.js`. See
        |neos-fusion-lsp|.

server.root_markers, server.root_fallback_markers, server.root_outermost,
server.root_fallback_to_file_dir
        See |neos-fusion-root|. `.git` is in `root_fallback_markers`, not in
        `root_markers`.

server.resolve_package_folders
        boolean, default `true`
        Resolve relative entries in `folders.packages` to absolute paths
        against the project root.

server.watch_files, server.watch_patterns
        boolean / string[], defaults `true` /
        `{ "*.fusion", "*.php", "*.yaml", "*.yml", "*.xlf" }`

server.progress.handle, server.progress.notify
        boolean, defaults `true`, `false`
        Handlers for the server's `custom/…` notifications.

server.on_attach, server.capabilities
        function | nil, table | nil

server.init_options
        table, default `{ textDocumentSync = { openClose = true } }`
        MUST stay set — without this value `initialize` fails on the server
        side.

server.settings.neosFusionLsp                   *neos-fusion-opt-settings*
        table
        Configuration of the server, fully pre-populated. Important branches:

            folders.packages          search paths for packages
            folders.fusion            Fusion folders inside a package
            folders.ignore            folders to skip
            logging.level             error|info|verbose|debug
            diagnostics.enabled       diagnostics on/off
            diagnostics.enabledDiagnostics   14 individual switches
            diagnostics.ignore.folders       default { "Packages/" }
            inlayHint.depth           disabled|literal|always

        The complete list is in `lua/neos_fusion/config.lua` and in
        `docs/ANALYSE.md`.

6. COMMANDS                                            *neos-fusion-commands*

                                              *:NeosFusionInstallServer*
:NeosFusionInstallServer [{version}]
        Installs `neos-fusion-ls` through npm into `server.install_dir`.

                                               *:NeosFusionUpdateServer*
:NeosFusionUpdateServer [{version}]
        Installs the given or configured version on top.

                                                 *:NeosFusionServerInfo*
:NeosFusionServerInfo
        Shows package, version, installation directory, resolved command and
        running clients.

                                                     *:NeosFusionStart*
                                                      *:NeosFusionStop*
                                                   *:NeosFusionRestart*
:NeosFusionStart / :NeosFusionStop / :NeosFusionRestart
        Start the client for the current buffer, stop all, restart.

                                            *:NeosFusionReloadWorkspace*
:NeosFusionReloadWorkspace
        Sends `workspace/didChangeConfiguration` again. The server then
        rebuilds all Fusion workspaces.

                                               *:NeosFusionSetLogLevel*
:NeosFusionSetLogLevel {level}
        `error`, `info`, `verbose` or `debug`. Also triggers a workspace
        reload.

                                                    *:NeosFusionDoctor*
:NeosFusionDoctor
        Diagnostics for the current buffer in a scratch buffer. Shows which
        `folders.packages` actually exist, which directories the project root
        contains, whether the file lies inside a `folders.fusion`, how many
        prototypes the server has indexed in total (`workspace/symbol`
        probe) and whether it knows the open file (`documentSymbol` probe).

        That separates the three causes of "hover/definition returns
        nothing":
            1. no configured package folder exists
            2. the file lies outside the Fusion folders
            3. the cursor is not on a supported target

                                                       *:NeosFusionLog*
:NeosFusionLog
        Opens |vim.lsp.get_log_path()| in a new tab.

:checkhealth neos_fusion                          *neos-fusion-checkhealth*
        Checks the Neovim version, Node/npm, the server installation, the
        start command, the wrapper, the project root, the Tree-sitter parser
        and the snippet engine.

7. LANGUAGE SERVER                                          *neos-fusion-lsp*

The server used is `neos-fusion-ls` (AGPL-3.0-or-later, Simon J. Schmidt),
the server behind the VSCode extension "Neos Fusion & AFX Language Server".
It is not bundled but fetched at runtime through npm.

Supported capabilities (from the `initialize` response):

    hover, goto definition, find references, document symbols,
    workspace symbols, completion, code actions, CodeLens, rename
    (with prepare), signature help, inlay hints, semantic tokens,
    diagnostics

Resolution of the start command, in this order:

    1. `server.cmd`
    2. `<root>/node_modules/neos-fusion-ls/out/main.js` (if prefer_local)
    3. the copy installed by the plugin in `server.install_dir`
    4. a globally installed copy through $PATH

The bin entry of the npm package is unusable: `out/main.js` has neither a
shebang nor an executable bit. The plugin therefore always calls
`node <path>/out/main.js --stdio`.

                                                   *neos-fusion-wrapper*
The server logs through `console.log()` to stdout, i.e. into the same stream
as the LSP framing. This goes unnoticed in VSCode, which uses IPC instead of
stdio. Neovim 0.12 does tolerate those lines, but the server logs are lost in
the process.

That is why the plugin starts the server through
`bin/neos-fusion-ls-stdio.js` by default. The wrapper loads the server in the
same process and redirects `console.*` to stderr beforehand: stdout stays
strictly LSP-conformant and the logs show up in |:NeosFusionLog|. Can be
turned off with `server.sanitize_stdout = false`.

                                                *neos-fusion-lsp-quirks*
Further quirks the plugin takes care of:

    - `initializationOptions.textDocumentSync.openClose` is mandatory.
    - Workspaces are only created from `workspaceFolders`.
    - Initialization happens on `workspace/didChangeConfiguration`; the
      settings therefore have to be complete.
    - `folders.packages` is checked against the working directory of the
      process; the plugin sets `cmd_cwd` and resolves the paths to absolute
      ones.
    - The server registers no file watchers; the plugin reports writes
      itself.

Evidence for all of this in `docs/ANALYSE.md`.

8. ROOT DETECTION                                          *neos-fusion-root*

Two-tier, walking upwards from the opened file.

Tier 1, strong markers (`server.root_markers`):

    flow, flow.bat, composer.json, DistributionPackages, Packages,
    Configuration/Settings.yaml

Tier 2, weak markers (`server.root_fallback_markers`), only when tier 1 stays
empty:

    .git

A `composer.json` only counts if it mentions `neos/neos`, `neos/flow`,
`neos/fusion` or `typo3/flow`. That keeps the composer.json of a single
package from becoming the project root.

Within a tier the outermost candidate wins by default
(`server.root_outermost`). Without any match the directory of the file is used
(`server.root_fallback_to_file_dir`).

Why two tiers: in monorepos the Neos project often lives in a subdirectory
(e.g. `repo/app/`) while `.git` sits at the repository root. A single-tier
list combined with `root_outermost` would then pick `repo/`; none of the
`folders.packages` exist there, the server indexes nothing, hover and goto
definition stay empty. Verify with |:NeosFusionDoctor|.

9. SYNTAX AND TREE-SITTER                                *neos-fusion-syntax*

The default path is the bundled `syntax/fusion.vim`.

The grammar `jirgn/tree-sitter-fusion` (MIT, as of 2021) exists, but
nvim-treesitter only carries it on the old branch `master`. On the current
branch `main` (used by LazyVim among others) it has been removed;
`:TSInstall fusion` reports `skipping unsupported language: fusion` there.
That is expected.

With nvim-treesitter on `master` the plugin picks up the parser automatically
(`treesitter.enable`) and uses the queries shipped there. The plugin provides
no Fusion queries of its own.

Measured limit of the grammar: AFX comments `{/* … */}` produce a parser
error. The Vim syntax covers them.

The only query file shipped is `after/queries/php/injections.scm` (additive
through `;; extends`, always active): Fusion inside PHP heredocs with the
identifier FUSION or AFX. The rule is deliberately narrow and not an
established Neos pattern.

`syntax/fusion.vim` covers prototypes, paths, operators, meta properties, Eel
expressions, AFX tags and attributes, strings, numbers, booleans, `null` as
well as `//`, `#` and `/* */` comments. Strings, Eel and AFX are regions so
that comment patterns do not bleed into literals.

Indentation: `indent/fusion.vim` handles `{}` blocks, AFX tags, multi-line
tags and `afx\``.

                                              *neos-fusion-textobjects*
The plugin provides no textobjects of its own. Without Tree-sitter they would
be too fragile for prototype blocks and AFX elements; with a parser,
`nvim-treesitter-textobjects` is the better choice.

10. SNIPPETS                                            *neos-fusion-snippets*

`snippets/fusion.json` in VSCode format. Prefixes include:

    component, contentcomponent, prototype, extend, renderer, eel,
    join, loop, map, datastructure, case, tag, value,
    @if, @process, @context, @apply, resource, translate,
    ignore, ignoreblock

With LuaSnip the registration happens automatically. Manually: >lua

    require("luasnip.loaders.from_vscode").lazy_load({
      paths = { require("neos_fusion.snippets").snippets_dir() },
    })
<
                                                *neos-fusion-snippets-blink*
blink.cmp, on the other hand, has to be configured. It does NOT search the
runtimepath, only `stdpath("config")/snippets` and runtimepath entries whose
path matches `friendly.snippets`. The plugin cannot fix that after the fact,
because blink builds its snippet registry once at setup time — before an
`ft`-lazy plugin exists. Add this to the blink spec: >lua

    {
      "saghen/blink.cmp",
      opts = function(_, opts)
        local dir = require("neos_fusion.snippets").snippets_dir()
        opts.sources = opts.sources or {}
        opts.sources.providers = opts.sources.providers or {}
        local provider = opts.sources.providers.snippets or {}
        provider.opts = provider.opts or {}
        local paths = provider.opts.search_paths
          or { vim.fn.stdpath("config") .. "/snippets" }
        if not vim.tbl_contains(paths, dir) then
          table.insert(paths, dir)
        end
        provider.opts.search_paths = paths
        opts.sources.providers.snippets = provider
      end,
    }
<
Then restart Neovim; `:Lazy reload` is not enough.
|neos-fusion-checkhealth| confirms the entry and otherwise shows the search
paths that are actually set.

12. TROUBLESHOOTING                              *neos-fusion-troubleshooting*

Always first: >vim

    :checkhealth neos_fusion    " installation
    :NeosFusionDoctor           " a specific project
<
The server only answers for prototype names, Fusion properties, Eel helpers,
resource URIs and controller/action references. So `K` showing "no
information available" on a string literal is normal.
No server found~
    :NeosFusionInstallServer, or set `server.cmd` explicitly.

Server runs but returns nothing~
    Wrong project root. :NeosFusionServerInfo shows `root`. The server also
    reports "No Packages found" or "composer.json not found". Then adjust
    `settings.neosFusionLsp.folders.packages`.

No diagnostics in Packages/~
    Intended: `diagnostics.ignore.folders` is set to `{ "Packages/" }`. With
    `diagnostics.alwaysDiagnoseChangedFile = true` changed files are checked
    anyway.

Changes to YAML/PHP have no effect~
    The plugin only reports BufWritePost. For changes made outside Neovim:
    :NeosFusionReloadWorkspace

Empty log~
    :NeosFusionSetLogLevel debug, then :NeosFusionLog. Server logs only show
    up with `server.sanitize_stdout = true`.

permission denied on node_modules/.bin/neos-fusion-ls~
    Expected — the file has no shebang. The plugin always calls
    `node …/out/main.js --stdio`.

Highlighting breaks off~
    :syntax sync fromstart, or install Tree-sitter.
